# Arduracer PSX — Code Audit, Top 20 Issues

Branch: `review/audit-2026-10` (worktree `.worktrees/review-2026-10`, rebased onto `main` @ `b30a271`)
Scope: `crates/arduracer-core` (14 files), `game/src` (33 files), `tools/*`, `Makefile`, CI.

Every issue below was verified by reading the source. Items 1–4 and 12 were additionally
**reproduced by execution** against the real crate (see "Reproductions").

## Tier 1 — Numerics. The fixed-point core silently returns wrong answers.

### 1. `Fixed::mul` truncates the i64 product instead of clamping — silent signed wraparound
`crates/arduracer-core/src/math.rs:78`

```rust
let prod = (self.0 as i64 * rhs.0 as i64) >> FP_SHIFT;
Fixed(prod as i32)          // truncating cast -> wraps
```

`Add`/`Sub` correctly use `saturating_add`/`saturating_sub` (lines 102/110). `Mul` does not.
Any `Fixed` product whose true value exceeds `i32::MAX` becomes large and **negative**,
poisoning every downstream value (velocity, distance, steering). This is the root cause of
issue 2.

### 2. `Vec2::length()` returns `0.00` for any separation >= ~800 units
`crates/arduracer-core/src/math.rs:151` (via `length_squared` -> `dot` -> wrapping `Mul`)

```rust
let sq = self.length_squared().raw();
if sq <= 0 { return Fixed::ZERO; }     // wrapped-negative -> ZERO
```

`length_squared` = `x*x + y*y`, where each product wraps (issue 1) and the sum saturates at
`i32::MIN`. This is the AI's **only** range measurement (`ai.rs:156`). `TRACK_19`/`TRACK_20`
are 30x30 = **1920 world units** wide, so rival-to-target distance is routinely 800–1900:

| input | `length()` | true |
|---|---|---|
| `vec(800, 0)` | **0.00** | 800 |
| `vec(1024, 0)` | **0.00** | 1024 |
| `vec(1500, 0)` | **390.96** | 1500 |
| `vec(1920, 0)` | **0.00** | 1920 |
| `vec(1900, 1900)` | **724.08** | 2687 |

Consequence: on the two biggest tracks the corner governor's lead term is zero, so **the AI
never brakes for corners**; at mid-range distances it brakes absurdly early.

### 3. `Fixed::div` returns 524288.0 on divide-by-zero, plus a second truncating cast
`crates/arduracer-core/src/math.rs:86-94`

```rust
if rhs.0 == 0 { return if self.0 >= 0 { Fixed(i32::MAX) } else { Fixed(i32::MIN) }; }
let quot = ((self.0 as i64) << FP_SHIFT) / (rhs.0 as i64);
Fixed(quot as i32)          // truncating cast
```

`Fixed::ONE / Fixed::ZERO` = **524287.9998 world units**. `vehicle.rs:316` uses a quotient
directly as a velocity scale factor, so a saturated value multiplies velocity by 131,072.
Separately, `Fixed::from_int(1000) / Fixed::from_raw(1)` = **-402653184** — a *negative*
scale factor from a positive/positive division.

### 4. Par times are mathematically unreachable on all 24 tracks — no medal can ever be earned
`crates/arduracer-core/src/levels.rs:136` (TRACK_01, representative)

```rust
par_times: ParTimes { bronze_ticks: 509, silver_ticks: 446,
                      gold_ticks: 398, dev_platinum_ticks: 323 },
```

`BASE_TOP_SPEED` = 14000 raw = **3.4179 u/tick** (`vehicle.rs:16`). The shortest legal road
path through TRACK_01's gates is **1792 units**. At absolute top speed in a perfectly
straight line — an unreachable lower bound that ignores cornering and the ~108-tick
acceleration ramp:

| medal | ticks | max reachable distance | vs 1792 needed |
|---|---|---|---|
| bronze | 509 | 1739.7 | **impossible** |
| silver | 446 | 1524.4 | **impossible** |
| gold | 398 | 1360.4 | **impossible** |
| dev_platinum | 323 | 1104.0 | **impossible** |

`bronze` requires 97–126% of the straight-line limit on every track. `ParTimes::evaluate_medal`
therefore always returns `Medal::None`, `SaveData::medals_earned` never leaves 0, and the
records/medals feature is dead. Root cause: par was generated as `route_length / top_speed`
with zero allowance for cornering. Meanwhile the AI laps 15–27% *faster* than the physical
floor (issue 20's neighbour, `ai.rs:123`), which is the visible symptom.

## Tier 2 — Gameplay state machines that trap or corrupt the player

### 5. A 1-tick lap scores Dev Platinum and is written to the memory card
`crates/arduracer-core/src/timing.rs:181`

```rust
if self.current_lap_ticks > 0 && self.current_lap_ticks < self.best_lap_ticks {
```

There is **no minimum plausible lap time** — `1` tick qualifies. Reproduced end-to-end:
complete one legitimate 600-tick lap, then cross the line again after 1 tick ->
`best_lap_ticks = 1` -> `evaluate_medal(1)` = `Medal::DevPlatinum` ->
`SaveData::update_best_lap` persists `best_lap_ticks[0] = 1`, `medals_earned[0] = 4`,
`max_unlocked_level = 2`, `is_valid() = true`. The medal/records system is defeated
permanently, from inside the game.

### 6. Checkpoint mask survives failed attempts -> a scored lap with no circuit driven
`crates/arduracer-core/src/timing.rs:164-179`

```rust
// order independent, anti-cheat by coverage
if self.checkpoints[i].contains_tile(tx, ty) { self.checkpoint_mask |= 1 << i; }
```

`checkpoint_mask` is cleared **only** on a scored lap. Reproduced: touch 2 gates -> cross the
line (no lap scored, mask keeps `0011`) -> touch the other 2 -> cross the line => **lap
scored with zero circuit driven**. Combined with order-independence, a lap requires only that
the *union* of all gate tiles ever touched is complete at the instant you leave the start
tile. On the 12–13 gate tracks that is a star tour, not a circuit.

### 7. Wall contact is a permanent, inescapable spin-out
`crates/arduracer-core/src/vehicle.rs:196`, `:294`, `:287`

```rust
if impact > HARD_IMPACT_THRESHOLD { ... self.drift.trigger_spinout(); }
...
let lateral_hold = if self.drift.is_spinning() { Fixed::ZERO } else { ... };  // no friction
...
if self.drift.is_spinning() { self.is_reversing = false; }                    // reverse disabled
```

Above 0.2197 u/tick into any wall the car spins for 60 ticks with **all** lateral velocity
preserved, zero friction, and reverse disabled — the player has no input authority. When the
60 ticks expire, the next wall contact starts a fresh 60-tick spin. Reproduced: **569 of 600
ticks in `SpinOut`, never recovered.** Only the manual respawn button frees the car.

### 8. `compute_standings` ranks on the raw gate index -> player shown 6th while leading
`crates/arduracer-core/src/championship.rs:136-146`

```rust
let gate_score = (gate_idx as i64) * 100_000;
let score = finish_bonus + lap_score + gate_score - dist_sq.min(99_999);
```

Two defects: `gate_score` (max 1.6M) is awarded for the *numeric index* while the positional
term is clamped to 99,999, so a larger index always wins regardless of where the car is; and
`target_gate_idx == checkpoint_count` (the start/finish node) maps through `% gate_count` to
`checkpoints[0]`, a completely different part of the track. Reproduced with all six cars on
the start tile: `standings = [1,2,3,4,5,0]` — **the player is displayed 6th**.

Compounding: `game/src/main.rs:368` feeds `route_node_index` (`timing.rs:218`, which returns
the *count* of cleared gates, not the next gate) into the same function that rivals enter with
their real `target_gate_idx`. Two different quantities are compared as one.

### 9. AI has no racing line, and laps faster than the circuit is physically long
`crates/arduracer-core/src/ai.rs:123`

```rust
TrackDef::gate_centre(&track.route_node(self.target_gate_idx as usize))
```

The rival beelines to the next gate centre — no path following, no road awareness. Measured on
TRACK_01 (1792-unit circuit => >=525-tick floor at `BASE_TOP_SPEED`): VIPER laps in **383
ticks (27% faster than physically possible)**, ROOKIE 445. VIPER also peaks at 4.72 u/tick
against the player's 3.418. Rivals get a large, permanent, invisible advantage.

## Tier 3 — Performance. One function alone can cost ~43% of the frame.

### 10. The HUD minimap rebuilds a *static* image from scratch every frame
`game/src/gpu/hud_renderer.rs:232-250`

```rust
for ty in 0..track.height as i32 {
    for tx in 0..track.width as i32 {
        ...
        gpu::draw_rect_flat(px, py, w, h, r, g, b);
```

No viewport culling, no caching — the loop walks the entire grid, every frame. Counting the
actual tile arrays against the per-tile rect cost (`Curb` = 5 rects, `StartFinish` = 34):

| track | grid | packets/frame | GP0 words/frame |
|---|---|---|---|
| Championship Final | 30x30 | **2,216** | **11,080** |
| Endurance Colosseum | 30x30 | 2,183 | 10,915 |
| Arduboy Oval | 10x10 | ~380 | ~1,900 |

Each `draw_rect_flat` is a `GPUSTAT` read plus 5 uncached GP0 stores. At ~110 cycles/packet
that is **~7.2 ms of the 16.67 ms frame (~43%)** reconstructing an image that only changes
when the track does. The circuit is static for the whole race and should be pre-rendered once
and blitted as a single sprite.

### 11. No frame synchronisation anywhere — double-buffering provides zero protection
`game/src/main.rs:193-194`, `psoxide/sdk/crates/psx-gpu/src/framebuf.rs:71-77`

```rust
psx_rt::interrupts::wait_vblank();
self.fb.swap();
```

The frame loop calls **no** `draw_sync()`, `signal_draw_done()`, `arm_draw_done()` or
`queue_gp1_at_vblank()`. `FrameBuffer::swap()` issues three raw `write_gp0` calls with **no**
`wait_cmd_ready()` — unlike every other GP0 writer in the SDK (`lib.rs:305`, `lib.rs:660`).
Three consequences: (a) if the 256-word command FIFO is full (likely, given issue 10) those
words are **dropped** and the draw area stays pointed at the previous buffer; (b) nothing
stops frame N+1 being submitted while VBlank flips to it, so the double buffer collapses to a
1-deep queue and the frame is scribbled as it is scanned; (c) `wait_vblank()` returns at the
*start* of VBlank, by definition mid-frame.

### 12. Zero `Barrier` tiles exist in any of the 24 grids — the entire wall system is dead code
`crates/arduracer-core/src/vehicle.rs:374`

Programmatic scan of all 24 `tiles` arrays: `Barrier` count = **0** on every track. So
`TrackTile::is_solid`, `SurfaceType::is_solid`, the whole interior-wall branch of
`collide_with_track`, and `SurfaceType::Barrier` (`max_speed_factor = 0`, `traction = 0`) are
**unreachable**. The comment claims "Solid interior walls (authored into the PSX Super
Stages)" — the four Super Stages have no walls at all. `BoostPad` is 0 on 20 tracks,
`OilSlick` 0 on 21.

This also hides a latent bug: `vehicle.rs:378-393` never corrects `self.position` after an
interior-solid hit (the outer bounds get a positional clamp at `:396-414`, interior solids do
not), and the face-selection heuristic claims the whole upper-left triangle *including the tile
centre*. The moment one `Barrier` tile is authored, cars get permanently embedded in walls.

## Tier 4 — Features advertised as shipped that do not exist

### 13. The cockpit canopy quad is degenerate — zero area — the windshield never renders
`game/src/gpu/car_renderer.rs:165`

```rust
let glass = make_quad(cx, cy, 4, 5, 4, -4, cos_raw, sin_raw);
```

`make_quad` (lines 34-41) negates `l_rear` internally: `transform_pt(cx, cy, -w_rear, -l_rear, ...)`.
Every other call site passes a **positive** `l_rear` (lines 118, 145, 155 -> `12`). Line 165
alone passes `-4`, which cancels the negation and puts all four vertices on the same `v = +4`
row. Measured twice-area: **0** at 0°, 90°, 180°, 270°; ~4 px² at intermediate angles against
the body's ~620. The "Tinted Cockpit Canopy" feature at `car_renderer.rs:9`/`:159` does not
exist on screen. Fix: `make_quad(cx, cy, 4, 5, 4, 4, ...)`.

### 14. Force feedback is 100% inert — `actuator_bytes()` has zero callers
`game/src/input/rumble.rs:89`, `game/src/input/mod.rs:35`

```rust
pub fn actuator_bytes(&self) -> (bool, u8) { (self.small_motor, self.large_motor) }
```

Never called anywhere in the repo. The vendored `psx-pad` exposes **no actuator/motor command
at all** — the only 8-byte transaction is the analog-enable command. `RumbleDriver` computes
motor states that are discarded every frame, and the analog-enable result is thrown away
(`let _ = ...`), so `PadTracker` is never used. GAME.md §1 and §7 list DualShock rumble as a
headline feature. There is also no "stop motors" call on pause/menu exit.

### 15. Curb rumble is permanently inaudible — the voice is never keyed on
`game/src/audio/sfx.rs:89-98`

```rust
if surface.triggers_curb_rumble() && player.speed > Fixed::from_raw(600) {
    let vol = Volume(0x0800);
    VOICE_SKID.set_volume(vol, vol);      // writes registers on a voice that was never started
    self.curb_playing = true;
```

`VOICE_SKID` is keyed on in exactly one place — the *drift* branch at `sfx.rs:59`. The curb
branch only writes volume/pitch on a stopped voice, and the `else` at `:93` calls `key_off`.
Rumble-strip audio never plays, on any surface, at any speed. REVIEW.md:466-468 explicitly
claims "curb chatter reuses the skid voice" as delivered.

Related in the same file: `if hit_wall { self.play_crash(); }` (`:101`) has **no edge
detector**, and `hit_wall` is true on *every frame* of a sustained scrape, so the 0.25s
crash sample is restarted 60x/second. And there is **no `key_off(VOICE_ENGINE)` anywhere**,
so the engine loop drones at the last RPM through every menu and the pause veil.

### 16. Tire smoke and sparks are drawn *before* the cars, then painted over
`game/src/main.rs:467` vs `:469-479`, `game/src/gpu/particles.rs:54`

```rust
self.particles.render(&self.camera, draw_y);              // particles FIRST
for rival in &self.rivals { render_car(...) }             // cars always on top
render_car(&self.player, &self.camera, draw_y, false, (220, 25, 45));
```

Smoke is emitted at the car's exact centre with `p.vel = Vec2::ZERO`, so it stays pinned under
the car for its whole 20-tick life while the opaque body quad paints over it. Sparks travel
only 0.5px/frame x 12 ticks = 6px from the centre, so they are ~90% occluded too. **The entire
particle system is effectively invisible.**

Related: cars are drawn in array order with the player unconditionally last, with **no depth
sorting at all** — in a top-down racer the only correct painter order is by screen/world Y, so
two overlapping cars visibly interpenetrate.

### 17. Zero semi-transparency in the entire renderer
`game/src/gpu/car_renderer.rs:146`, `gpu/particles.rs:110`, `gpu/skidmarks.rs:98`

`draw_quad_flat`/`draw_rect_flat`/`draw_tri_flat` build their commands with
`polygon_opcode(..., semi_transparent = false)` hard-wired. So: the ghost car is **fully
opaque** solid blue, not a translucent phantom; the smoke "fade" is 3 discrete opaque greys
with hard edges; the skidmark "fade" is a single binary colour step. TODO.md:222 (TASK-305)
specifies "Semi-transparent particle engine … additive blending (`GPU_BLEND_ADD`) for sparks"
and is marked `[x]`. `BlendMode` appears nowhere in `game/src`.

Also confirmed absent from `game/src` entirely: **any texture page, CLUT or `fill_rect`
usage** (VRAM is 29% used — 71% idle), and **dithering is never enabled** (`gpu::init()`'s
`GP1(01h)` reset clears it and nothing re-enables it). Quantising the palette through the
PS1's 5-bit VRAM path shows `SPEEDWAY.road` (44,46,52) and `SPEEDWAY.road2` (40,42,48) collapse
to the **identical** BGR555 word `0x14A6` — so the "dark asphalt underlay" under every timing
gate is byte-identical to the surrounding tarmac on tracks 1-6.

## Tier 5 — Testing and CI. The safety net reports green while testing nothing.

### 18. `cargo test` on the core crate runs zero tests and exits 0
`Makefile:146-150`, `.github/workflows/ci.yml:57`

```
$ cargo test --manifest-path crates/arduracer-core/Cargo.toml
running 0 tests
test result: ok. 0 passed; 0 failed; ...
```

`grep -rc "#\[test\]" crates/arduracer-core/src/` -> **0 matches across all 14 files**. The
entire core (physics, drift, AI, timing, save, tracks, ghost) has no in-crate tests. CI prints
`Running host-side game logic tests in crates/arduracer-core...` and goes green having executed
nothing. This is the direct reason issues 1–9 survived: every one of them is a two-line
property test away from being caught. There is no `proptest`/`quickcheck`/`cargo-fuzz`/`rand`
anywhere despite AGENT.md:29 advertising "Sweeps, **Fuzzers**, Bit-flip Verification".

Aggravating: `tools/test_game_logic/src/main.rs:19-26` catches panics with
`println!("FAIL: {:?}", e)` — `{:?}` on `Box<dyn Any + Send>` prints literally `Any { .. }`, so
a red CI run emits 42 identical content-free failure lines.

### 19. The `game` crate is entirely outside clippy, and cannot be tested at all
`.github/workflows/ci.yml:46-52`

The clippy job lists five crates; `game` is absent (it is only `fmt`-checked). Locally
`cargo clippy --release --all-targets` in `game/` fails with `error[E0463]: can't find crate
for 'test'` — structural, because `game/.cargo/config.toml` sets `build-std = ["core"]`, so no
`test`/`std` crate exists for the bare-metal target. Plain `cargo clippy --release` reports
**34 warnings** (incl. `clippy::empty_loop` at `main.rs:567`, 12x `new_without_default`).

Consequence: the largest and most hardware-risky code — the 570-line `main.rs` containing the
entire screen state machine and every audio state transition in issue 15 — gets **zero lint
coverage and is unreachable from any test**. Only `ui/pause_input.rs` and `memcard.rs` are
host-testable, via a `#[path = ...]` textual-include trick that is not applied to the other 15
modules.

Also: playtest par-time drift does **not** fail CI (`tools/playtest/src/main.rs:402` computes
`mismatched` but never adds it to `all_errors`), so any physics change that shifts lap times
prints a friendly `"ok (needs recal)"` and CI stays green.

### 20. Race entry never syncs the pause menu's edge baseline — the game pauses itself on frame 1
`game/src/main.rs:276` vs `:304`

```rust
let frame = self.pause.update_from_pad(&pad);              // 276 — every racing frame
...
self.pause.sync_edges(PauseMenu::input_from_pad(&pad));   // 304 — ONLY on RestartRace
```

`load_track` (`:261`) never calls `sync_edges`, and `PauseMenu::new()` initialises
`prev.start = false`. `Start` is a confirm button on three consecutive screens (`menu.rs:62`,
`track_select.rs:72`, `tuning_screen.rs:104`). Repro: hold `Start` from the title -> Main Menu
-> Track Select -> **the race loads already paused**, music stopped, requiring a second
`Start` press. This is exactly the bug class `sync_edges` was written to prevent (see its own
doc comment at `pause_input.rs:137-143`).

**Paired with a silent-data-loss bug in the same session flow:** the garage allows sliders
**0..=10** (`tuning_screen.rs:74`, `.min(10)`, with `saturating_sub` making 0 reachable) but
`CarTuning::is_valid()` requires **1..=7** (`tuning.rs:9,11`). `memcard.rs:219` then drops the
setup:
```rust
if slot < 3 && tuning.is_valid() { self.save_data.tuning_slots[slot] = tuning; ... }
```
`flush()` is still called unconditionally but `store_tuning` never set `is_dirty`, so
`flush_with` returns early **without any error banner or message**. Any setup with one axis
outside 1–7 is silently discarded on exit. GAME.md §3.2 documents the range as 1–7.

## Recommended order of work

**Block 1 — numerics (1, 2, 3).** One-day fix: make `Mul`/`Div` saturating and reimplement
`Vec2::length()` in i64 with a proper integer sqrt. Nothing else in this list is trustworthy
until this lands; issues 4, 7 and 9 are all downstream symptoms.

**Block 2 — gameplay correctness (5, 6, 7, 8).** Add a minimum plausible lap time; clear
`checkpoint_mask` on any start-line crossing rather than only a scored one; give the spin-out
some friction and keep reverse available; rank standings by a real progress metric instead of
`gate_idx * 100_000`.

**Block 3 — performance (10, 11).** Pre-render the minimap once into VRAM and blit it; add
proper `draw_sync`/`queue_gp1_at_vblank` frame pacing. Together these are worth back most of a
frame.

**Block 4 — honesty pass (13, 14, 15, 17).** Fix the `l_rear` sign; either wire an actuator
write path in `psx-pad` or delete `RumbleDriver`; add the missing `key_on` and the
`hit_wall` edge detector; then either implement blending/textures or correct the `[x]` marks in
TODO.md and REVIEW.md.

**Block 5 — process (18, 19).** Move `tools/test_game_logic` into `#[cfg(test)]` modules in
`arduracer-core` — that alone fixes the false green, the `Any { .. }` output, and gives
per-test reporting/filtering. Add the `game` crate to clippy (drop `--all-targets`) and make
playtest par drift fail the build.

**Block 6 — content (12, 4).** Author `Barrier` geometry for the Super Stages, and regenerate
par times from the playtest reference driver with a cornering-aware model.
